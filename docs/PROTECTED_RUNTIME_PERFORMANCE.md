# Protected Runtime Performance Rule

受保护发布版本必须保持低负载、低卡顿，并支持长时间稳定运行。

任何保护机制、健康检查、完整性校验、热更新、`AI_AGENT_POLICY` 检测、签名验证、日志采集、Web 预览或诊断逻辑，都不得在高频运行路径中造成明显卡顿。

## 强制要求

1. 受保护版本必须作为最终性能基准。
2. 开发版本通过测试不代表受保护版本通过测试。
3. 每次发布前必须测试受保护产物，而不只测试源码开发版本。
4. 完整性校验可以严格，但不得高频重复扫描大文件。
5. 健康检查必须尽量保持 `O(1)`，默认只读取缓存状态。
6. 高频调度路径不得执行完整 SHA-256 扫描、Manifest 全量验证、策略文件全文检测或大型对象序列化。
7. Web 预览、日志、诊断和热更新检查不得抢占偷菜、种植、施肥和好友巡查主流程。
8. 受保护包新增任何保护逻辑时，必须评估其运行时性能影响。
9. 受保护版出现卡顿时，优先检查保护链、健康检查、日志、预览、CDP 往返和大型对象返回，不能直接归因于小游戏本身。
10. 不允许为了增加保护而牺牲长时间挂机的稳定性，也不允许为了降低卡顿而削弱开发版已有功能或偷菜成功率。

## 验收标准

发布前必须确认：

- 受保护包可以正常启动。
- 受保护包完整性校验通过。
- 连续健康检查不会重复计算全量哈希。
- 高频健康检查不会阻塞自动化。
- 长时间运行时不会因为保护逻辑持续占用 CPU 或 IO。
- Web 预览关闭时不产生截图开销。
- 日志默认不输出大型对象。
- `button-lite.js` 仍满足体积限制。
- Protected dry-run 产物通过签名、篡改、泄漏和 Windows 解压验证。
- 受保护版本实机运行体验不低于开发版本。
